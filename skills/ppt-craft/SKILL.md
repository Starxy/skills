# PPT 内容、页面与逐字稿

PPT 的根本目的是高效传递学术信息、讲清楚、让人听明白并便于讨论交流：内容决定学术价值，形式服务于内容与现场表达，不让形式反向束缚内容。

## 全局边界与默认约定

以下约束适用于全部任务与环节，不在后续步骤中重复定义：

- **交付边界**：新建或整体重构 PPT 时，在 PPT 制作并检查定稿后**默认最后输出一份逐字稿**（独立讲稿文档；若用户明确声明不需要则省略；若用户要求写入或整理内嵌演讲者备注则按要求处理）。仅做局部修改或只讨论方案时，按对应范围交付。
- **模板归属与样式边界**：
  - 用户提供自定义 PPT 模板、参考课件或指定视觉风格时，沿用其母版、配色、字体、标题区与版式规范。
  - 修改既有 PPT 时，用户未要求更换风格则保留原样式；用户明确要求按默认学术蓝风格或指定新模板修改时，按目标模板彻底重构。仅修改逐字稿或备注时不改动页面版式。
  - 未提供模板且未指定其他风格时，默认采用[学术蓝默认模板](references/academic-blue-style.md)。
- **内容与表达底线**：遵循“表不如图、字不如表”优先级；文字采用正式书面语，全篇不出现中文句号 `。`，科学问题与核心问题不使用问号 `？`；数学符号与公式采用专业 LaTeX 形式；不凭空补造材料中不存在的事实、数据或图表。

## 标准执行工作流

新建或整体重构 PPT 按**三阶段内容设计（详见[内容设计](references/content-design.md#三阶段内容设计)）→ 制作 PPT 与成品核查 → 最后输出逐字稿**推进：

1. **第一阶段：确认场景、基本要求与材料支撑**
   - 核查用户提供的论文、文档、数据、图表或既有文件是否足以支撑目标 PPT；若关键内容、数据或原始图件缺失或冲突，列出缺口并追问补充。
   - 与用户确认 PPT 的适用场景（如课题开题/中期/结题/学术交流/课题简介、论文分享、讲座等）及基本要求（汇报目标、听众背景、页数或时长、章节要求、模板来源）；未明确时及时提问，必要时继续追问。
   - **局部修改分支**：仅需对既有 PPT 做局部修改（改单页文字/图表、微调局部页组、只处理逐字稿或备注）时，查看目标页及前后相连页面、确认修改范围与材料无缺口后，直接转入步骤 4 起的对应环节，无需重做整篇大纲。
2. **第二阶段：输出简要大纲文档并等待用户确认**（新建或整体重构 PPT 必经环节）
   - 读取[内容设计](references/content-design.md)，通读全部资料并按确认后的场景构思汇报方案。**本阶段不考虑版面设计与展示文字约束，只聚焦汇报主线思路、学术故事、章节划分与逻辑推进**。
   - **用户未提供大纲设计稿时**：完成自检后向用户输出一份**简要大纲 Markdown 文档**，并在回复中说明**目录划分、总页数与简要汇报逻辑**；若用户提出修改事项则同步调整并再次确认，**待用户确认大纲后再进入第三阶段**。
   - **用户已提供大纲或明确跳过确认**：核对其与材料、场景匹配且无重大缺口后直接进入第三阶段（跳过确认时仍须在内部完成大纲自检）。
3. **第三阶段：编写逐页详细设计文档**
   - 用户确认大纲后，基于已确认的全局思路、汇报主线与章节划分，按[全局边界与默认约定](#全局边界与默认约定)锁定模板规范（默认风格读[学术蓝默认模板](references/academic-blue-style.md)），结合[内容设计](references/content-design.md#由大纲落到单页与连续页组衔接)、[展示文字写作风格与反防御要求](references/writing-style.md)与[页面与图表](references/visual-design.md)，产出一份**逐页详细设计 Markdown 文档**——明确每一页的模板适配、排版布局、拟用图表/公式与适合展示的页面文字，同时保证页面之间的连贯性。
4. **制作 PPT 成品**（逐页详细设计文档完成后直接执行）
   - 得到逐页详细设计文档后，直接按目标模板规范、[页面与图表](references/visual-design.md)与[展示文字写作风格与反防御要求](references/writing-style.md)制作 PPT 文件。
5. **PPT 成品检查与修正**
   - 读取[修改与交付](references/revision-delivery.md)，按改动范围核查保存文件的渲染版面、文字标点、公式图表与备注状态，发现问题直接修正并复查受影响页面。
6. **输出逐字稿与最终交付**（PPT 制作完成之后最后执行）
   - 读取[逐字稿与备注](references/speaker-notes.md)，按最终定稿的页序与画面默认编写并输出一份连贯自然的口语逐字稿（如用户要求写入内嵌演讲者备注则同步写入并清理）；交付 PPT 与逐字稿的明确文件路径，并如实说明未检查项。
