# PPT 内容、页面与逐字稿

PPT 的根本目的是高效传递学术信息、讲清楚、让人听明白并便于讨论交流：内容决定学术价值，形式服务于内容与现场表达，不让形式反向束缚内容。

## 全局边界与默认约定

以下约束适用于全部任务与环节，不在后续步骤中重复定义：

- **交付边界**：默认只制作并交付 PPT 页面，不生成逐字稿，也不写入演讲者备注；仅在用户明确要求时才编写讲稿或处理备注。只讨论方案时只交付方案。
- **模板归属与样式边界**：
  - 用户提供自定义 PPT 模板、参考课件或指定视觉风格时，沿用其母版、配色、字体、标题区与版式规范。
  - 修改既有 PPT 时，用户未要求更换风格则保留原样式；用户明确要求按默认学术蓝风格或指定新模板修改时，按目标模板彻底重构。仅修改逐字稿或备注时不改动页面版式。
  - 未提供模板且未指定其他风格时，默认采用[学术蓝默认模板](references/academic-blue-style.md)。
- **内容与表达底线**：遵循“表不如图、字不如表”优先级；文字采用正式书面语，全篇不出现中文句号 `。`，科学问题与核心问题不使用问号 `？`；数学符号与公式采用专业 LaTeX 形式；不凭空补造材料中不存在的事实、数据或图表。

## 标准执行工作流

1. **评估材料与明确适用场景**
   - **判断材料是否支撑制作**：先通读用户提供的论文、文档、数据、图表或既有文件，核查是否具备支撑目标 PPT 所需的核心论点、方法细节、结果数据与原始图件；材料不足、关键内容缺失或存在冲突时，明确列出缺口并追问补充。
   - **明确适用场景与汇报目标**：当用户未明确 PPT 的适用场景（如课题开题/中期/结题/学术交流/课题简介、论文分享、课程或专题讲座等）时，**及时向用户提问确认**；必要时追问听众背景、汇报时长、重点侧重或模板要求等目标信息。
   - **局部修改分支**：仅需对既有 PPT 做局部修改（改单页文字/图表、微调局部页组、只处理逐字稿或备注）时，先查看目标页及前后相连页面、确认修改范围与材料无缺口后，直接转入步骤 3 起的对应环节，无需重做整篇大纲。
2. **大纲设计与用户确认**（新建或整体重构 PPT 必经环节）
   - **用户未提供大纲设计稿时**：读取[内容设计](references/content-design.md)，依据核实后的材料与适用场景组织大纲并完成[检查内容方案](references/content-design.md#检查内容方案)，随后：
     - 输出一份具体的**大纲设计 Markdown 文档**（写明适用场景、核心主题思路、目录划分、总页数、各章节递进关系、每页核心判断及拟用材料）；
     - 在回复中向用户简要说明 **PPT 的目录划分、总页数与汇报逻辑**，请用户确认或提出修改意见，必要时继续追问以明确目标。
   - **迭代与放行条件**：收到修改事项则按意见调整大纲设计 Markdown 文档并再次说明改动；**待用户确认大纲之后，再正式开始步骤 3 的 PPT 制作**。
   - **用户已提供大纲或跳过确认**：用户已提供大纲设计稿时，核对其与材料、适用场景是否匹配，存在缺口或歧义时先追问确认，无异议则按该大纲进入步骤 3；若用户明确指令跳过大纲确认且场景与材料充分，在内部完成大纲通检后直接进入制作。
3. **页面制作与视觉排版**（确认大纲后正式执行）
   - 按[全局边界与默认约定](#全局边界与默认约定)确定样式基准；使用默认学术蓝风格时读取[学术蓝默认模板](references/academic-blue-style.md)。
   - 读取[展示文字写作风格与反防御要求](references/writing-style.md)撰写页面文字，读取[页面与图表](references/visual-design.md)落实图文表混排、插画生成、无框分层排版、间距与 LaTeX 公式。
4. **逐字稿与备注处理**（仅在用户明确要求时执行）
   - 读取[逐字稿与备注](references/speaker-notes.md)，按连续页组编写口语讲稿，或写入并清理内嵌演讲者备注。
5. **成品检查与交付**
   - 读取[修改与交付](references/revision-delivery.md)，按改动范围核查保存文件的渲染版面、文字标点、公式图表与备注状态，交付明确文件路径并如实说明未检查项。
