# PPT 内容、页面与逐字稿

围绕听众需要掌握的认识组织整场讲述，让页面承载关键判断、材料和长句逻辑，让讲稿完成连续推演，交付能够直接展示、讲述和继续编辑的文件。

## 明确任务与默认样式

从请求和材料中明确听众、用途、时长、参考内容、采用样式和修改范围。用户当前明确要求优先于本 skill 默认做法；信息足够时直接制作或修改文件，只询问确实无法判断、又会改变讲述主线或修改对象的问题。只讨论方案时交付方案。

新建 PPT 默认使用 **学术蓝默认模板**：配色、封面、目录和章节首页沿用学术蓝固有样式；内容页顶部蓝色章节栏内放章节名，其下居中放置一句带下划线的核心标题，正文多用卡片或清晰分栏配合完整长句。随附示例是一份真实主题的组会论文汇报，只用来示范风格与常见版式，制作具体 PPT 时不照搬示例的章节结构或固定逻辑。用户指定了其他样式或修改既有 PPT 时，保留其原有样式；只改逐字稿或备注时不改动页面版式。

## 按需读取参考文档

只读取与当前任务相关的参考文档；局部修订复用已确认的整体安排，补读受影响部分即可。

| 当前工作 | 读取材料 | 要解决的问题 |
| --- | --- | --- |
| 新建大纲、调整章节或案例深度 | [内容设计](references/content-design.md) | 整场回答什么，各部分和页组怎样推进理解 |
| 排版页面、处理图表或写页面文字 | [页面与图表](references/visual-design.md) | 屏幕放什么内容，怎样让图表和长句清晰可读 |
| 配逐字稿、改试讲稿或整理备注 | [逐字稿与备注](references/speaker-notes.md) | 怎样自然连贯地讲清，口播与查证信息怎样分开 |
| 修改既有文件或检查交付结果 | [修改与交付](references/revision-delivery.md) | 怎样保留手改内容，并对改后的文件做相应检查 |
| 使用默认学术蓝模板做页面 | [学术蓝默认模板](references/academic-blue-style.md) | 确定学术蓝的配色、字体、卡片版式、长句标点与按需脚注，不照搬示例固定内容 |

## 按当前阶段推进

### 新建或重构

先确定整场要回答的核心问题和主要判断，再安排各部分职责与前后承接，随后规划连续页组，最后落定页面文字、图表和口播。每页和每项主要材料都要能推进理解，重复或偏题的内容合并或删去；页数、图文比例和时长分配服从内容需要。先按[检查内容方案](references/content-design.md#检查内容方案)核对大纲再做页面；只要求方案时在这一步交付。

### 既有 PPT 配稿

通读全部页面标题、正文、图表和已有备注，按章节和连续页组起草讲稿，再对应具体页码。只要求写讲稿时，把补充解释放进讲稿，需要调整页面或页序才能解决的问题另列具体建议；同步改 PPT 时直接调整。

### 局部修改

先看目标页及前后衔接，判断反馈改变的是结构、解释深度、措辞、版式还是备注，在对应层级修改。同一套文件内有同类问题时一并处理，并检查前后页承接是否受影响。

## 页面文字、表述与脚注

| 载体 | 主要职责 |
| --- | --- |
| 页面正文与图表 | 用正式、简洁、能独立读懂的书面表达，呈现核心判断、对象、条件、机制和结果 |
| 演讲者备注 | 提供可以直接朗读的口语化解释、读图引导和页间过渡 |
| 图注与技术标注 | 就近放在图表旁，标明变量、单位、图例和影响结果解读的条件 |
| 参考文献脚注 | 仅在引用他人论文原图、原表、数据或核心观点且需注明出处时添加 |
| 独立讲稿与备课资料 | 按任务保留补充讲述、完整文献出处、图号定位和待核对事项 |

页面可见文字（含标题、正文、图注与表格内容）按以下原则取舍：

- **居中核心标题与完整长句**：内容页顶部放一句居中的核心标题（常见形式如“方面：核心概括”或一句简洁判断），概括本页重点；正文和表格说明采用完整、自洽的书面长句，使听众不听口播也能读懂逻辑。留白优于硬凑字数。
- **展示与口播分开**：删去“接下来看”“如下图所示”等纯口语过渡或无信息增量的套话；连续推演和过渡衔接写入演讲者备注，定义、图例和条件留在屏幕。
- **直陈事实与条件**：核对过程、制作说明和预防质疑的辩解留在制作过程处理，不写进页面或讲稿。影响结果解读的方法条件、适用范围和局限性，在相关方法、结果或讨论页直接写明。
- **教学示意自然呈现**：听众结合标题和上下文能看出属于举例、类比或概念示意时，不加“虚构”“仅供示意”等免责声明；只有图形本身可能让人把示意误当成真实数据时，才修正标题或图内标签。
- **克制结论框与文献脚注**：不默认在每页底部放总结框或参考文献脚注；仅在页面确有需要单独强调的结论，或确需标明他人文献出处时才添加。不强制每页要点数量或固定结构。

保留确需交代的图例、单位、条件和来源，不把模拟示例写成真实结果；具体数字、时间先后和强断言核对原始材料。

## 制作与检查

使用当前环境可用的演示文稿工具或文件处理库完成制作和编辑，按具体需要选择实现方式。交付前核对用户实际使用的产物：

- **大纲与讲稿**：连读主讲内容，确认前提、指代、术语和指图与页面对应，时长估算说明依据（未实际试讲不写实际测得时长）。
- **PPT 文件**：按[修改与交付](references/revision-delivery.md#按改动检查文件)核对最终保存的文件；环境支持渲染或打开查看时，检查页面文字、排版与受影响页面；改动备注时核对最终文件中的备注正文与格式。

交付明确的文件位置，简要说明主要改动；若因工具限制有未检查的项目（如缺少渲染工具未核对画面），如实说明即可。
