# 修改与交付

## 找准版本与修改范围

动手前先明确要改哪个文件、参照哪份样式、允许调整哪些页面或对象。如果是续写或改写用户已有文件，继续沿用未被撤销的母版、字体、标点、配色和备注约定；页序有变动时，以标题和页面内容为准定位目标，不硬套旧页码。

沿用旧的生成脚本或历史模板时，清理里面残留的旧标题、旧页码、已删案例，以及自动生成的多余页脚或默认注释框，避免新页面把旧问题带回来。

只要求修改备注、脚注或独立讲稿时，只改对应对象，不顺带重排无关页面；遇到必须调整版式或页序才能解决的问题，先列出具体修改建议。

## 保留原有格式与处理占用

修改既有 PPT 时，优先使用能无损读写原对象、备注、公式、图表和媒体的方式，尽量保留用户手改过的排版、图表和文字格式，不随意整页重建而弄丢原有样式。

如果目标 PPT 正被其他程序打开无法覆盖保存，可先保存为一个明确的临时可用副本，并在交付时说明文件名及还需合并的内容，避免用户误当成最终原文件。

## 关联材料与文件整理

保留约定的正式文件名，避免同一目录下堆积多个“最终版”“修改版”。只有当任务包含关联材料时，才同步更新目录页码、大纲、独立讲稿或拆章/总稿文件，并核对页码变更后的前后引用与指图位置。生成 PDF 或其他派生物按用户需要提供；渲染检查产生的中间图片无需一并交付。

## 按改动检查文件

交付前针对本次改动的范围做对应检查，未改动且此前已确认的部分不必重复折腾：

| 本次改动 | 应检查的内容 |
| --- | --- |
| 新建整套 PPT 或重构整章 | 通读主线与页面衔接；在可用工具中查看页面文字、长句断行、图文与表格对齐及受影响备注 |
| 单页内容或版式修改 | 查看修改页的版面与文字溢出情况，确认前后衔接和讲稿指图未脱节 |
| 全局样式或母版调整 | 抽查或通览受样式影响的页面，核对字体、配色、标题区样式、版式结构及按需脚注一致性 |
| 仅修改或清理备注 | 读取最终保存文件中的备注正文，确认口播连贯、无参考链接残留、无多余空行和异常段距 |
| 仅修改独立讲稿 | 连读改动页组，核对页码、标题和出处整理；说明 PPT 原文件未改动 |
| 调整页序、拆章或合并 | 核对目录页码、章节编号、前后引用以及图片和备注是否随页对应 |
| 替换图片、公式或视频 | 检查清晰度、纵横比和公式符号；视频如有条件可用播放器核对起止片段 |

检查时以实际保存的最终文件为准，不单看代码输出；发现错位、溢出或多余字句直接改好再复查受影响页面。

## 交付与说明

交付时给出明确的文件路径，简要交代改动内容、已做的检查以及受环境限制尚未核对的部分（例如缺少渲染工具未查看实际画面、或缺少视频播放条件未试播），不把大纲或中间草稿说成已验证完成的成品。

收到用户修改意见后，分清哪些属于本次特定要求（例如某个场合的页数或时间限制），哪些属于可复用的习惯，在本次文件中落实修改即可，不把单次特例硬套成所有 PPT 的固定规范。
