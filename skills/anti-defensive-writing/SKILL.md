# 科研写作与阶段汇报

写清这项工作解决什么问题、目前发现什么，以及读者据此可以作出什么判断。围绕有用且有证据的贡献组织内容，给探索、迭代、局部改进和合理权衡留下空间。

## 确定当前任务

从请求和材料判断**用途、研究阶段、修改范围**。用途决定如何组织，阶段决定可以说到什么程度；即使写投稿摘要，也应按实际证据表述。

沿用用户指定的语言、篇幅和格式。未指定时，沿用原稿语言；无原稿则使用中文。先用已有材料回答问题，直接处理能完成的部分；只有查不到且会改变关键事实或研究判断的信息才提问，其余缺口可在相应位置简短标注。局部润色只处理相关段落，不自动扩成选题审查或完整实验规划。

按实际任务读取对应参考文件：

| 任务 | 读取要求 |
| --- | --- |
| 措辞润色、一般专业说明、技术方案或 SOP 的文字修改 | 使用本文件即可 |
| Idea、研究定位、开题、proposal、实验计划 | 读取 [研究规划](references/research-planning.md) |
| 实验记录、实验报告、预实验总结、组会、周报、中期或阶段汇报 | 读取 [实验与进展](references/experiments-and-progress.md) |
| 论文整体组织、摘要、引言、结果、讨论、结论、rebuttal | 读取 [论文与审稿回复](references/papers-and-rebuttals.md)；单纯措辞小修仍只用本文件 |
| 难以判断怎样删掉防御语气又保留原意 | 按需读取 [改写示例](references/rewrite-examples.md) |

只读取当前任务涉及的文件。已读内容及有效结果直接复用；内容变更、缺失或版本不明且影响判断时再补读。混合文稿按段落用途处理，例如组会中的论文构思和实验诊断可以采用不同结构。

## 共同规则

1. **具体说清对象、动作与结果。** 开头呈现观点、发现或操作；删除只为预防想象中质疑而写的辩解。把“严谨”“稳定”“有实质支撑”等评价改成实际做了什么、得到什么；有对应定义、测量或引用的专业用法保留。“基线”“证据”等词需要具体所指，不按禁词表机械替换。每段围绕一个要点展开，避免术语堆叠、自造标签和无依据保证；需要概念比较时再使用对照句。
2. **用具体条件表达分寸。** 保留会改变结论解释、适用范围或操作含义的条件，在需要的位置说清即可。未开展的工作按当前主张判断是否需要说明，不逐项列为不足。根据事实保留“初步”“可能”“未观察到”等措辞；减少的是重复保留语气。SOP 的参数、前置条件、禁止事项和操作目的属于内容，不能在润色中改掉。
3. **结论与实际获得的结果相称。** 区分实际观察、待验证解释和后续计划，通常用动词和时态即可。保持数据、比较条件、引用和因果强度准确；无支持的主张改小或删去，不换一组抽象词。检查数量、程序完成或格式正确各有其证明范围，不能自动证明研究效果。需要外部依据时核对来源，缺失的实验结果留作缺口，不能补写成事实。
4. **按实际贡献评价工作。** 关注问题价值、相对已有工作的具体增量和证据质量。接受有意义的组合、适配、复现、资源建设、经验发现与成本改进；说明它们增加了什么知识或能力。创新要求依据研究目标和投稿定位判断，不默认要求每个模块原创、所有指标领先或一次研究解决全部问题。
5. **只增加有明确用途的工作。** 根据用户目标、现有结果和可说明的问题选择补充工作，保留已有必要要求。新增检索、实验、文档或审查应说明它解决哪个未知、检查什么错误，或支持哪项判断；“更严谨”本身不是理由。区分当前必需、下一阶段需要和可选扩展。达到本次交付要求后结束，只有变更、失败或未解决的关键问题才触发相关复核。

## 组织与改写

先从材料中找出读者最需要知道的判断，再选择支持它的事实。措辞修改围绕该判断精简；整体改写才调整章节、论证顺序和重点。叙事可以随发现改变，已经观察到的事实保持不变。

处理不理想结果时，描述具体发生了什么及其对主张的影响。只有材料支持时才解释原因或称为权衡。一个局部结果不足以否定整项工作；直接推翻核心主张的结果则应改变结论。写作中压缩或转移展示内容，不删除原始实验记录。

采用适合读者的自然段；并列结果、配置和比较用表格或列表。篇幅来自所需信息，避免把每段写成固定模板。

## 交付与完成

默认交付用户请求的成稿、改稿或方案。修改说明只保留会影响用户使用结果的变更；必要缺口放在相关位置或一段简短说明中。进度只报告有信息价值的发现或判断变化；纠错写明错处及具体修正。不要附送完整自查表、潜在审稿问题清单或新的“局限性”段落。

交付前检查一次：事实与数量是否保持准确，主要判断是否清楚，证据阶段是否匹配，关键条件是否保留，重复辩解是否删净，请求范围是否完成。发现具体问题就修正，随后交付。
