# 中文翻译流程

仅在主文件的“可选中文译稿的触发条件”全部满足，且当前处理范围的英文润色稿已复核定稿后读取。中文稿是英文定稿的附加译稿；英文润色阶段的原语言输出规则不限制本阶段的中文表达。

## 1. 锁定翻译底稿与结构

以英文定稿为唯一翻译底稿，不重新翻译原始 ASR，不把润色时删除的卡顿或废弃自纠带回译稿。先确认所有待处理英文块均已完成润色与复核，再开始翻译；长稿也遵守这一先后顺序。当前处理范围由用户提供或指定的原文决定，不能把工具内部的分块当作独立处理范围以提前启动翻译。

按英文定稿识别标题、自然段、列表项、引用、表格、代码块及字幕条目，维护内部对应关系。每个英文正文单元都必须有且只有一个中文对应单元。允许为了中文语法在同一自然段内部调整句子结构或拆合句子，保持信息顺序与逻辑关系。

完成标准：英文底稿已固定，中文稿的结构和覆盖范围可逐项与其对照。

## 2. 统一术语并逐段翻译

- 术语优先采用用户提供且适合当前语境的英中对照；其次使用该领域、该含义下已经确认的通行译法。同一概念全文保持同一译名，同一英文词的不同含义分别按上下文处理，不做机械全局替换。
- 没有可靠中文译名时保留英文术语。只在避免歧义确有必要时附原英文，不增加源稿没有的定义、缩写展开或背景解释。需要查证时核对权威术语来源，查询所得事实不补入正文。
- 保留产品名、模型名、版本号、代码、命令、路径、URL、函数名和配置键的规范写法。链接显示文字可以翻译，链接目标、代码内容及数学符号保持不变。
- 依据前后段与说话人关系翻译指代、省略、连接词和转述，保持第一人称、发言归属及语气。仅在指代对象明确时作必要的中文补足，不为连贯而猜测对象或补写过渡论证。
- 准确保留否定范围、情态强度、量词、成立条件、比较关系和不确定性。例如 `not always` 对应“不总是”，`not necessarily` 对应“不一定”，`only if` 所表达的必要条件不能译成充分条件。
- 数值、范围、日期、单位、比例与版本信息保持语义一致，特别区分“百分比”与“百分点”。保留原文事实及原有矛盾，不在翻译中纠正观点或替说话人下结论。
- 译文使用自然、连贯的中文，保留例子、反例、旁支说明、问答及重复强调；不以中文摘要替代翻译，不因中文表达长度不同而删减内容。
- 英文底稿中的存疑词仍保持存疑，不能在中文稿中猜定其含义。已有编辑标记保留对应位置及不确定程度，可使用统一的中文对等标记；不要把“词义存疑”改写成“听不清”。

长稿沿英文定稿的结构分块翻译，复用其对应位置并维护英中术语对照与未解决的指代。邻文只用于理解，不在接缝处重复翻译。所有对应记录和术语表默认只用于内部核对，不附入正文。

以下例子用于核对语义，不作为固定替换表：

| 英文定稿 | 中文译法 | 保留的含义 |
| --- | --- | --- |
| It doesn't always work offline. | 它并非总能离线运行。 | 不是“完全不能离线运行”。 |
| It might reduce latency by up to 10%. | 它可能使延迟最多降低 10%。 | 保留可能性和上限，没有承诺必然降低 10%。 |
| We retry only if the request is idempotent. | 只有请求具有幂等性时，我们才会重试。 | 幂等性是必要条件，并不表示满足它就一定重试。 |

## 3. 保持格式并核对语义

中文稿沿用英文定稿的结构，不重新按中文的标题密度或每段句数规则排版：

| 英文定稿元素 | 中文稿处理 |
| --- | --- |
| 标题 | 翻译标题文字，保持位置、数量、层级及编号 |
| 自然段 | 一段对应一段，保持顺序；仅在段内按中文语法调整句子 |
| 列表、引用、表格 | 保持项目、层级、引用格式、行列与顺序，翻译其中的自然语言 |
| 时间戳与说话人标识 | 原样保留数值、标签及其对应发言位置 |
| 代码与链接 | 保留代码块语言标签、代码内容、行内标识符和链接目标 |
| SRT / VTT 字幕 | 保留格式头、编号、起止时间、条目顺序与文本换行对应关系，只翻译自然语言内容，不重新计时 |

逐单元对照英文定稿，检查漏译、重复、术语误译、指代错接，以及数字、否定和条件的改变；再连读中文稿检查跨段衔接。对没有把握的语义保持原有不确定性。

翻译时若发现英文底稿仍有实质错误，先回到英文编辑规则复核并修订英文，再同步修订对应译文；不能只在中文稿中修正出另一层意思。

完成标准：英文所有正文单元均有中文对应，结构一致，关键语义和术语一致，译文完整、连贯；两份稿件对应同一版英文定稿。

## 4. 交付两份文稿

沿用用户指定的格式与保存位置，分别交付英文润色稿和中文译稿。保存文件且没有指定名称时，使用 `<原文件名>.polished.en.md` 和 `<原文件名>.polished.zh.md`；粘贴输入以 `transcript` 为文件名基础。纯文本或字幕使用相应扩展名，两份稿件保持相同文件格式。已有指定英文文件名时保留，并为中文稿使用可辨认的对应名称；重名时追加序号，不覆盖原文或无关文件。

两份全文可直接在聊天容纳时，先交付完整英文稿，再交付完整中文稿，仅用文稿之外的最简语言标签区分两份内容，不改变各自正文的标题级别。默认不逐段交错、不改成双语对照表，也不附翻译说明、术语表或总结。

篇幅超出单条回复容量时，优先保存完整的两份文件并提供链接。用户要求仅聊天或环境无法写入文件时，在自然边界分批交付，分别标明英文稿与中文稿的已交付范围和下一续接位置。容量不足不能成为压缩译文或声称两份稿件均已完成的理由。
