# 长文本处理

在原文无法一次容纳、分批到达，或完整输出超出单条回复容量时读取。编辑判断沿用 `SKILL.md`；这里仅处理分块、连续性和交付，分块不改变润色力度。

## 读取与分块

1. 按用户给出的顺序处理文件或片段。先检查实际长度、首尾、时间或段号是否连续；工具返回内容被截断时，继续读取未返回的范围，不把截断结果当作全文。顺序确实无法判断且影响衔接时，才补问顺序。
2. 全文较长时先按范围浏览结构与术语，再逐块精读和编辑；扫描不能替代任何一块的完整阅读。无法取得后文时，只对已取得范围作判断，不假定后续内容。
3. 优先在主题、完整例子、问答结束或自然段边界切块。块大小取决于当前上下文和输出余量；每块须容纳原文、必要邻文和润色稿，不按固定分钟数强行切断发言。
4. 为每块指定唯一的核心范围，使用现有字幕编号、段号或文件行号定位。没有稳定编号时使用段落位置及首尾短语；时间戳可辅助定位，但不单独作为唯一标识。
5. 相邻块可附带前后 1–2 个自然段作为上下文。每段正文只归一个核心范围；附带部分只用于理解和接缝复核，不再重复输出。不把上一块润色稿当成下一块原文。

只有带共同来源锚点或充分上下文证据的重叠才去重。文字相似但处于不同时间或讲述位置时，先按真实重述保留。发现输入缺号或缺段时记录缺口，不生成过渡句掩盖缺失。

## 最小连续性记录

分块期间维护以下信息；它们用于续接与核对，不并入正文：

| 记录 | 内容 |
| --- | --- |
| 覆盖 | 来源文件、块顺序、核心范围、首尾锚点，以及未处理 / 已编辑 / 已对照状态 |
| 术语 | 已确认的规范写法、指代的实体与版本、对应原文位置；存疑项单列 |
| 衔接 | 当前说话人、上一个标题、未结束的例子或论证，以及实际需要的少量邻文 |
| 交付 | 已写入或已交付范围、下一个核心范围与输出文件位置 |

这些记录不能替代原文。原文始终保留，用于回查每个例子、数字和限定条件。需要跨上下文或中断恢复时，将最小记录和分块稿保存为本地工作文件；短任务不为流程而创建额外文件。

## 逐块编辑与合并

1. 每块开始前读取术语记录与必要邻文，按主文件规则处理核心范围。不要因位置靠后、内容相似或输出空间变少而改成概述。
2. 编辑完即对照该块原文，确认每段实质信息有去向，核对数字、否定、条件和说话人，再标为已对照。长度明显缩短或扩张时回查原因，不用字数比例代替内容核验。
3. 后文确认先前存疑术语时，回查同一实体的旧稿再统一写法；仍有歧义的出现位置保持原样。文件成稿可在交付前统一修订，已在聊天交付的内容如有实质纠正则明确指出位置与改法。
4. 合并相邻稿件时，对照边界两侧的原文，确认句子、代词、例子、问答轮次和标题完整衔接。只去除工作流程引入的重叠，不删录音本身的回顾或强调。
5. 合并后按覆盖记录检查所有核心范围恰好出现一次，再检查全文术语和标题密度。确认第一块起点和最后一块终点分别到达本次输入首尾，且全部块已对照，才认定整理完成。

## 文件与分批交付

优先使用用户指定的保存位置与格式。需要保存长稿但未指定位置时，在允许写入的工作目录保存 `<原文件名>.polished.md`；粘贴输入使用 `transcript.polished.md`。用户要求纯文本或字幕时使用对应扩展名与结构。重名时添加序号，除非用户要求更新既有稿件，不覆盖原文或旧稿。

可以逐块写入独立工作稿再合并，以避免单次输出限制。恢复工作时按核心范围替换或合并对应工作稿，不盲目追加已完成内容；完整稿通过核对后再交付其可点击链接。

用户要求只在聊天输出，或环境无法写入文件时，沿原文顺序在自然边界分批交付。正文之外仅标明本批范围、尚未完成状态和下一续接锚点，不用省略号或摘要替代剩余原文。需要下一轮才能继续时明确说明，不把当前一批称为全文，也不暗示系统会自动发送后续消息。

用户分批提供原文时，维护同一套术语和覆盖记录，直接处理当前可见部分；收到后续材料再衔接。没有读到未提供的材料，就不声明整段视频已完成。
